# LittleDays 开发规范文档目录

本文档目录包含了 LittleDays iOS 项目的所有开发规范和约定。

---

## 📋 新会话必读

**⚠️ 重要：在开始任何开发工作之前，必须完成以下阅读步骤！**

### 第一步：理解开发规范

必须阅读以下规范文档，理解项目开发要求：

1. **[开发规范](./development-conventions.md)** ⭐⭐⭐
   - 文档和注释语言规范
   - Swift 编码规范
   - SwiftUI 开发规范
   - Core Data 规范
   - 测试规范
   - iOS 安全规范

2. **[代码提交流程](./code-submission-workflow.md)** ⭐⭐⭐⭐⭐
   - 修改后必须验证
   - 验证步骤（编译、启动、功能测试）
   - 只有验证通过才能提交
   - 提交前必须得到用户确认

3. **[需求设计工作流程](./requirements-design-workflow.md)** ⭐⭐⭐⭐⭐
   - 需求讨论流程
   - 方案设计流程
   - 方案确认和归档流程
   - 实施规划要求

### 第二步：理解项目结构

阅读项目 README.md，了解项目组织结构和关键文件位置。

### 第三步：理解项目关键约束

阅读 **[项目关键约束](./project-constraints.md)**，了解：
- 技术栈约束（Swift、SwiftUI、iOS 版本等）
- 功能范围约束（必须实现和已移除的功能）
- 工作流程约束（关键决策流程）

### 第四步：确认理解

在开始工作前，确认你已经：

- [ ] 阅读并理解了开发规范
- [ ] 阅读并理解了代码提交流程
- [ ] 阅读并理解了项目关键约束
- [ ] 阅读并理解了需求设计工作流程（如需进行需求设计）
- [ ] 了解了项目目录结构
- [ ] 理解了关键约束和禁止行为

## 📖 规范文档使用指南

### 日常开发

每次会话开始时：
1. 阅读本文档目录
2. 阅读开发规范
3. 阅读代码提交流程

### 功能开发

开发新功能时：
1. 阅读需求设计工作流程
2. 完成需求讨论和方案设计
3. 按照开发规范实施
4. 按照代码提交流程提交

### 代码审查

审查代码时：
1. 检查是否符合开发规范
2. 检查是否遵循了代码提交流程
3. 检查是否有违反项目关键约束的地方
