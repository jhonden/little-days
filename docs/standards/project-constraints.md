# 项目关键约束

本文档定义了 LittleDays iOS 项目的技术栈约束、功能范围约束和工作流程约束。

---

## 1. 技术栈约束

### 1.1 核心技术栈

| 技术 | 版本要求 | 用途 |
|------|---------|------|
| Swift | 5.0+ | 开发语言 |
| SwiftUI | iOS 17.0+ | UI 框架 |
| Xcode | 15.0+ | 开发工具 |
| iOS SDK | 17.0+ | 系统要求 |
| Core Data | - | 数据持久化 |
| Vision Framework | - | 图像识别 |
| Core ML | - | 本地 AI |

### 1.2 可选技术栈

| 技术 | 版本要求 | 用途 | 备注 |
|------|---------|------|------|
| UIKit | iOS 17.0+ | 传统 UI 框架 | 仅在必要时使用 |
| OpenAI API | - | 云端 AI | 本地 AI 效果不好时迁移 |

### 1.3 第三方库约束

**Swift Package Manager 依赖：**
- 避免过度依赖第三方库
- 优先使用系统原生框架
- 如需使用第三方库，必须：
  - 有良好的文档和社区支持
  - 保持活跃更新
  - 开源协议友好（MIT、Apache 2.0 等）

**禁止使用的库：**
- 未维护或长期不更新的库
- 协议不明确的库
- 来源不明的库

## 3. 工作流程约束

### 3.1 开发流程约束

**强制遵循：**
- 需求设计 → 方案确认 → 实施开发 → 验证测试 → 代码提交
- 遵循 [需求设计工作流程](./requirements-design-workflow.md)
- 遵循 [代码提交流程](./code-submission-workflow.md)

**禁止行为：**
- ❌ 跳过需求设计直接开发
- ❌ 未经方案确认开始编码
- ❌ 验证失败时提交代码

### 3.2 Git 分支策略

- **main 分支**：稳定的发布版本
- **feature 分支**：功能开发分支（如 `feature/wardrobe-add-clothing`）
- **fix 分支**：Bug 修复分支（如 `fix/crash-on-save`）

### 3.3 代码审查流程

- 代码提交前必须：
  - 通过编译验证
  - 通过功能验证
  - 得到用户确认

## 4. 架构约束

### 4.1 必须遵循的架构模式

**MVVM 架构：**
- View 层：SwiftUI 组件
- ViewModel 层：ObservableObject
- Model 层：Struct + Codable

**依赖倒置原则（DIP）：**
- AI 服务必须通过 Protocol 抽象
- 业务层依赖抽象，不依赖具体实现

### 4.2 禁止的架构模式

- ❌ MVC（老式 UIKit 模式）
- ❌ 直接在 View 中放置业务逻辑
- ❌ ViewModel 引用 UI 组件

### 4.3 模块化约束

- 每个功能模块独立开发
- 模块间通过接口通信
- 避免模块间直接依赖

---

## 5. 数据存储约束

### 5.1 Core Data 使用约束

**必须使用 Core Data：**
- 衣服数据持久化
- 穿搭记录（未来版本）

**可选存储方式：**
- UserDefaults：用户偏好设置
- Keychain：敏感数据（如云端 API Key）
- 文件系统：图片、文档等大文件

### 5.2 数据模型约束

- 所有 Model 必须遵循 `Codable` 协议
- 列表展示的 Model 必须遵循 `Identifiable` 协议
- 避免过度复杂的数据关系

## 6. UI/UX 约束

### 6.1 设计风格

- 温馨、可爱、有温度
- 主色调：橙色系（#FF9500）
- 圆角设计、卡片式布局

### 6.2 设计约束

- 遵循 iOS Human Interface Guidelines
- 适配暗黑模式（Dark Mode）
- 适配不同屏幕尺寸（iPhone SE 到 iPhone 15 Pro Max）
- 支持横屏（如需要）

### 6.3 禁止的 UI 设计

- ❌ 不符合 iOS 设计规范的界面
- ❌ 过度复杂的动画效果
- ❌ 影响性能的复杂布局

---

## 7. 性能约束

### 7.1 启动性能

- 冷启动时间：< 3 秒
- 热启动时间：< 1 秒

### 7.2 运行时性能

- 列表滚动：60 FPS
- 图片加载：渐进式加载，占位图优先
- AI 识别：响应时间 < 5 秒（本地 AI）

### 7.3 内存管理

- 避免内存泄漏
- 及时释放大图片资源
- 使用 `weak` 引用避免循环引用

## 8. 安全约束

### 8.1 权限管理

**需要申请的权限：**
- 相机权限：拍照录入衣服
- 照片库权限：选择照片

**权限申请要求：**
- 在 Info.plist 中说明使用目的
- 提前检查权限状态
- 优雅处理权限拒绝

### 8.2 数据安全

- 敏感数据使用 Keychain 存储
- 网络通信使用 HTTPS
- 对用户输入进行验证

## 10. 已知限制和注意事项

### 10.1 技术限制

- **本地 AI 能力有限**：Core ML 模型需要训练，识别精度可能不如云端 AI
- **Core Data 性能**：大量数据时需要优化查询和索引
- **图片存储**：图片占用存储空间大，需要考虑压缩和清理策略

### 10.2 功能限制

- **单设备使用**：不支持多设备同步
- **单用户使用**：不支持多用户
- **离线使用**：本地 AI 可离线，云端 AI 需要网络

### 10.3 开发限制

- **Xcode 独占**：需要 Xcode 开发环境
- **iOS 限制**：无法在 Android 运行

## 11. 关键决策点

### 11.1 AI 方案选择

**决策节点：本地 AI 效果是否满足需求？**

- 满足 → 继续使用本地 AI
- 不满足 → 迁移到云端 AI（架构已支持）

### 11.2 数据存储方案

**决策节点：Core Data 是否满足需求？**

- 满足 → 继续使用 Core Data
- 不满足 → 评估 Realm 或 SQLite

### 11.3 UI 框架选择

**决策节点：SwiftUI 是否满足需求？**

- 满足 → 继续使用 SwiftUI
- 不满足 → 考虑 UIKit（极少数情况）
